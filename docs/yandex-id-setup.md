# Вход через Яндекс ID — что нужно настроить

Код готов (этап 2). Осталось зарегистрировать приложение в Яндексе и прописать ключи.

## 1. Зарегистрировать приложение

1. Открыть **https://oauth.yandex.ru/client/new** под аккаунтом компании.
2. Название: «Улётная Парковка». Платформы — отметить **веб-сервисы** и **приложение**.
3. **Доступы (scopes)** — отметить только нужное:
   - `login:email` — адрес почты (обязательно, по нему связываем аккаунты);
   - `login:info` — имя и фамилия;
   - `login:phone` — телефон (необязательно; если дадите — телефон подтянется сам,
     и клиенту не придётся вводить его при первой броне).
4. **Redirect URI** — добавить оба:
   - веб-кабинет: `https://api.uletnayaparkovka.ru/api/auth/yandex/callback`
   - приложение: `uletnaya://auth/yandex`
5. Сохранить. Забрать **ClientID** и **Client secret**.

## 2. Прописать ключи

**Сервер** (`.env.production` API, там же где `DATABASE_URL`):

```
YANDEX_CLIENT_ID=<ClientID>
YANDEX_CLIENT_SECRET=<Client secret>
```

**Приложение** — `apps/mobile/app.json`, поле `extra.yandexClientId`:

```json
"yandexClientId": "<ClientID>"
```

> `client_secret` в приложение **не кладём** — обмен кода на токен делает сервер.
> Пока переменные пустые, кнопка «Войти через Яндекс» просто не показывается —
> ни в приложении, ни в кабинете. Всё остальное работает как обычно.

## 3. Применить миграцию

```bash
psql "$DATABASE_URL" -f packages/db/migrations/2026-08-15_yandex-id.sql
```

## 4. Пересобрать приложение

Вход через Яндекс добавляет нативные модули (`expo-auth-session`, `expo-web-browser`,
`expo-crypto`) — **OTA-обновления недостаточно**, нужна новая сборка:

```bash
cd apps/mobile
eas build --platform all --profile production
eas submit --platform ios --profile production
```

Веб-кабинет заработает сразу после деплоя API — пересборка ему не нужна.

## Как это устроено

- Приложение и кабинет получают от Яндекса **authorization code** (в приложении — с PKCE).
- Код уходит на наш сервер, он меняет его на токен Яндекса (`client_secret` только тут)
  и запрашивает профиль: `https://login.yandex.ru/info`, заголовок `Authorization: OAuth <token>`.
- Сервер сверяет `client_id` из ответа со своим — чужой токен не примет.
- Пользователь ищется по `yandex_id`, затем по почте (Яндекс её подтверждает,
  поэтому привязка к существующему аккаунту безопасна), иначе создаётся новый.
- Телефон из Яндекса берётся, только если он не занят другим аккаунтом.
