# Глава 2. Почему заявок мало (диагноз)

## 2.1 Аналитический разрез

Прежде чем лечить, диагностируем. Ниже — гипотезы причин «мало заявок», ранжированные по влиянию.

### 2.1.1 Трафик мал (главное)
По косвенным признакам (sitemap из 19 страниц, отсутствие активных SEO-постов, нет признаков активной контекстной рекламы) — органический трафик низкий. Конкуренты (`parking24pitstop.ru`, `parking-svo.ru`) имеют в разы больше посещаемости и поэтому в разы больше заявок при той же конверсии. Нет смысла вкладываться в конверсию, если трафика 50 человек в день.

### 2.1.2 Сайт виден поисковикам плохо
- **Шаблонные title и description** — нет региональной заточки, нет коммерческих слов («заказать», «забронировать», «дешево»).
- **Нет блога** — поисковики любят свежий контент.
- **Нет схемы Local Business / Parking** — Яндекс и Google не показывают сниппет с рейтингом, ценой, телефоном.
- **Нет sitemap для приоритетных страниц** — page-sitemap.xml есть, но без приоритетов и lastmod на горячих страницах.

### 2.1.3 Низкая конверсия на странице
Калькулятор работает, но:
- **uCalc открывается медленно** — внешний скрипт.
- **Нет «срочного» элемента** (счётчик уходящих свободных мест, скидка до конца недели).
- **Нет всплывающих окон возврата** — посетитель уходит → теряется.
- **Нет повторного захвата контакта** — нет «Заказать обратный звонок».

### 2.1.4 Нет ретеншена
- Пользователь, который один раз забронировал, **не получает напоминаний о следующих перелётах** — нет email-цепочки, нет SMS-маркетинга, нет push-уведомлений из приложения по факту посадочной с инсайтом «вы прилетели — забронируйте сразу обратный заезд».

### 2.1.5 Платных каналов нет / слабые
- **Контекстной рекламы Яндекс.Директ не видно** по бренду в чужих запросах.
- **Нет ремаркетинга** — посетитель ушёл и забыл.
- **Нет Telegram Ads** — целевая аудитория (путешественники из Москвы, бизнес-командировки) тусуется в туристических каналах.

### 2.1.6 Слабая мобильная воронка
Мобильное приложение есть, но:
- Заявки не доходят до менеджера (см. главу 3).
- В сторах нет промо-материалов (скриншоты, видео, описание).
- Нет ASO (App Store Optimization) — поиск в RuStore «парковка шереметьево» не показывает нас выше.

## 2.2 Конкурентный разрыв

Из глав 2-3 нашего 10x-blueprint.pdf:
- **parking-svo.ru** — лидер рынка, 11 лет, **150 000+ клиентов**, 4.9★, **2000 броней/мес**
- **parking24pitstop.ru** — №2, у них больше броней через сайт за счёт конверсии (виджет на главной, отзывы, гарантии)
- **uletnayaparkovka.ru** — топ-3 по сервису, но **в 5-10 раз меньше броней** при сильнее продукте (мобильное приложение, договор хранения, трансфер с 1-го дня)

Главный посыл: **наш продукт лучше, маркетинг хуже**. Лечим маркетинг.

# Глава 3. Что нужно от заказчика для запуска мобильных заявок

Это **первая задача** — без неё мобильное приложение не имеет смысла продвигать. Ниже — пошаговый чек-лист «что и где получить, кому переслать».

## 3.1 Telegram-бот для уведомлений

**Цель:** Каждая новая бронь / заявка с сайта или приложения мгновенно прилетает в Telegram-группу менеджеров.

### Шаг 1. Создаём бота (5 минут)
1. Открыть в Telegram бота **@BotFather**
2. Команда `/newbot`
3. Дать имя «Улётная Парковка Заявки» (или любое)
4. Дать username, например `uletnaya_leads_bot`
5. BotFather пришлёт **токен** вида `123456789:ABCdefGHIjklMNOpqrSTUvwxYZ` — **сохранить**, это `TELEGRAM_BOT_TOKEN`

### Шаг 2. Создаём группу и получаем chat_id (5 минут)
1. Создать новую группу «Улётная Заявки» в Telegram
2. Добавить туда созданного бота админом
3. Кто-то из участников отправляет в группу любое сообщение
4. Открыть в браузере: `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
5. Найти в ответе поле `"chat":{"id":-1001234567890,...` — это `TELEGRAM_CHAT_ID` (со знаком минус, если группа)

### Шаг 3. Прислать значения
Заказчик присылает в защищённый канал (1Password, Bitwarden, ЛС в защищённой Telegram, GPG):
```
TELEGRAM_BOT_TOKEN=123456789:ABCdef...
TELEGRAM_CHAT_ID=-1001234567890
```

После этого в течение 5 минут — все заявки летят в группу.

## 3.2 SMTP для отправки email

**Цель:** Менеджер получает копию заявки на почту, клиент — подтверждение бронирования с фирменным письмом.

### Вариант A — Gmail App Password (быстрее)
1. Включить **2FA** для Google-аккаунта `uletnayaparkovka@gmail.com`
2. Перейти на https://myaccount.google.com/apppasswords
3. Создать новый пароль «Uletnaya Booking»
4. Получить 16-символьный пароль вида `abcd efgh ijkl mnop`
5. Прислать:
```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_USER=uletnayaparkovka@gmail.com
SMTP_PASS=abcdefghijklmnop
SMTP_FROM="Улётная Парковка <uletnayaparkovka@gmail.com>"
SMTP_TO=uletnayaparkovka@gmail.com
```

### Вариант B — Beget SMTP (через хостинг)
1. В панели Beget создать почтовый ящик `noreply@uletnayaparkovka.ru`
2. Прислать значения от ящика:
```
SMTP_HOST=smtp.beget.com
SMTP_PORT=465
SMTP_USER=noreply@uletnayaparkovka.ru
SMTP_PASS=<пароль_ящика>
SMTP_FROM="Улётная Парковка <noreply@uletnayaparkovka.ru>"
SMTP_TO=uletnayaparkovka@gmail.com
```

## 3.3 amoCRM реальные OAuth-токены

**Цель:** Каждая бронь / заявка автоматически создаётся как сделка в воронке amoCRM. Менеджер ведёт сделку в привычной CRM.

### Шаг 1. Зайти в amoCRM
1. Открыть `https://<ваш-домен>.amocrm.ru` (для Улётной — `vsteh.amocrm.ru` по конфигу или другой)
2. **Настройки** → **Интеграции** → **Создать интеграцию**

### Шаг 2. Заполнить форму интеграции
- Название: «Улётная Парковка API»
- Тип: **Внешняя интеграция / Веб-сервис**
- URL для перенаправления: `https://api.uletnayaparkovka.ru/api/webhooks/amocrm/oauth`
- Разрешения: **Доступ ко всем данным аккаунта**

### Шаг 3. Получить ключи
amoCRM выдаст:
- `AMOCRM_CLIENT_ID` — UUID
- `AMOCRM_CLIENT_SECRET` — строка
- **Код авторизации** (одноразовый) — нужно сразу обменять на refresh-token

### Шаг 4. Обменять код на refresh-token
Подрядчик выполнит один curl-запрос на сервере, получит `AMOCRM_REFRESH_TOKEN` и `AMOCRM_DOMAIN`.

Подробно — в `docs/09-amocrm-live-sync.md` в репо.

## 3.4 SMS.ru для реального SMS

**Цель:** Реальные SMS-коды для входа в приложение. Сейчас в STUB-режиме код всегда `111111` — для App Store это нормально, для реальных пользователей — категорически нет.

### Шаг 1. Зарегистрироваться на sms.ru
1. https://sms.ru → регистрация под ИП
2. Подтверждение через паспорт + ИНН
3. Стартовый депозит **500-1000 ₽**

### Шаг 2. Получить API ID
В личном кабинете → **API** → копировать `api_id` — это GUID вида `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` (36 символов)

### Шаг 3. Подтвердить отправителя (3-5 дней)
1. Запросить регистрацию имени отправителя `Uletnaya`
2. Прислать в sms.ru договор хранения, подтверждающий род деятельности
3. После одобрения SMS будут приходить от имени `Uletnaya`, а не безымянного номера

### Шаг 4. Прислать значения
```
SMSRU_API_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
SMSRU_FROM=Uletnaya
SMS_PROVIDER=smsru
```

После этого приложение начнёт слать реальные SMS, а админ сможет видеть статус каждого SMS в кабинете sms.ru.

# Глава 4. SEO-стратегия — как не платить за каждого посетителя

Контекстная реклама даёт быстрый результат, но дорого. SEO даёт **бесплатный трафик навсегда**, но требует 60-90 дней раскачки. Поэтому SEO запускаем СЕЙЧАС, эффект через 2-3 месяца.

# Глава 7. Email и SMS-маркетинг — ретеншен и возврат

Привлечь нового клиента стоит 200-300 ₽. Вернуть старого — почти бесплатно. Поэтому ретеншен критичен.

## 7.1 Email-цепочки

### Цепочка «Welcome» (для тех, кто оставил email при первой брони)
1. **День 0:** «Подтверждение бронирования» — фирменное письмо с деталями, картой, QR-кодом для входа на парковку
2. **День 1 (перед поездкой):** «Завтра вылет — все готово?» — напоминание, ссылка на расписание трансфера
3. **День Заезда:** «Доехали? Наш диспетчер +7 909 914 88 81 ждёт звонка» — упрощает первый контакт
4. **День Возврата:** «Спасибо что выбрали Улётную! Оставьте отзыв на Я.Картах за 500 баллов»
5. **Через неделю:** «5 хитростей для следующей поездки» — полезный контент
6. **Через месяц:** «Скоро в командировку? Мы помним вашу машину — бронь в 1 клик»

### Сегментация
- Часто летающие (2+ брони за 3 мес) → отдельная цепочка с премиум-сегментом
- Долгие парковки (от 14 дней) → отдельные акции на длительный тариф
- Корпоративные (B2B) → отдельная коммуникация

## 7.2 SMS-маркетинг

Дороже email, но открываемость 95% против 25% у email.

Использовать только для:
- Подтверждения брони с QR-кодом
- Напоминания за 1 день до заезда
- Промоакций сезонных (раз в месяц максимум)

Бюджет: 5 000 ₽/мес при 1000 SMS (5 ₽ за SMS на sms.ru).

## 7.3 Push-уведомления в приложении

Если клиент скачал приложение — это золотая возможность для коммуникации.

Сценарии:
- **«Бесплатные баллы за отзыв»** — через 1 день после возврата машины
- **«Скидка к следующей поездке»** — через 1 месяц после прошлой брони
- **«Сезонные акции»** — Новый год, лето, ноябрь (раз в квартал)
- **«День рождения»** — если есть дата → скидка 10%

## 7.4 Программа лояльности (упрощённая стратегия)

В приложении уже реализована программа баллов. Активно продвигаем:

- **1 ₽ = 1 балл** при каждой брони
- **Бронзовый** уровень — 1% кэшбэк
- **Серебряный** — 3% кэшбэк после 5 броней
- **Золотой** — 5% кэшбэк после 15 броней
- **Реферальная программа:** «Пригласи друга → 500 ₽ тебе + 500 ₽ ему»

Каждая бронь повышает лояльность, каждый друг — +1 клиент почти бесплатно.

# Глава 10. Мобильное приложение — ASO и продвижение

## 10.1 App Store Optimization (ASO)

Сейчас приложение в RuStore и в iOS TestFlight. Когда выйдет в App Store — нужно оптимизировать:

### iOS
- **Title:** «Улётная Пит-стоп парковка»
- **Subtitle:** «Парковка Шереметьево с трансфером»
- **Keywords (100 символов):** «парковка,шереметьево,трансфер,svo,командировка,аэропорт,перехват,москва,airport,svo»
- **Description:** 4000 символов — расписываем все фишки
- **Скриншоты:** 5 штук:
  1. Главный экран «Парковка от 150 ₽/сутки»
  2. Калькулятор «Бронь за 30 секунд»
  3. Карта «5 минут до Шереметьево»
  4. Бонусы «1 ₽ = 1 балл»
  5. Подтверждение «Бронирование подтверждено»

### Android / RuStore / Google Play
- Same approach, но дополнительно использовать promo-видео 30 сек на главной карточке

## 10.2 Промо в App Store / RuStore

- **App Store Search Ads** (в РФ ограничено) — пропускаем
- **RuStore промо-баннеры** — есть платная опция продвижения, 30-50 ₽/установка
- **Cross-promo в Telegram-канале** — «Скачайте приложение, бронируйте за 1 клик» + скидка

## 10.3 Глубокие ссылки и App Links

Когда клиент кликает на сайт `/booking?utm=...` → проверяем, есть ли установленное приложение → открываем сразу там. Сильно повышает retention.

## 10.4 Push-уведомления — стратегия

Push-уведомления имеют CTR 20-30% (выше email и SMS). Используем умно:
- **Welcome push** через 1 час после установки: «Бронируйте за 30 секунд — введите даты»
- **Триггер push** когда клиент уже использует калькулятор, но не бронирует: «Цена снизится через 15 минут — закрепите сейчас»
- **Локальный push** через 12 часов после последней брони: «Спасибо! Расскажите, как прошла поездка»
- **Сезонный** раз в месяц с акциями
- **NEVER spam** — больше 1 пуша в неделю — отписка

# Глава 11. Аналитика и трекинг

Никогда не работаем «вслепую». Все каналы измеряются.

## 11.1 Что подключить

### На сайте
- **Яндекс.Метрика** — основной инструмент. Цели:
  - Открытие калькулятора
  - Заполнение калькулятора
  - Отправка заявки
  - Скачивание PDF тарифов
  - Звонок (через Callibri или другой call-tracking)
- **Google Tag Manager** — управление пикселями
- **VK Pixel** — для ремаркетинга
- **Facebook Pixel** — даже если реклама не идёт, для будущего

### В мобильном приложении
- **AppMetrica** (Я.Аппметрика) — основное
- **Firebase Analytics** — для Android
- **AdjustOpens / Adjust** — для атрибуции

### В amoCRM
- **UTM-метки** — каждая заявка приходит с UTM. Видим, какой канал работает
- **Воронка сделок** — настраиваем правильно: «Новая → В работе → Подтверждена → Активна → Завершена / Отменена»
- **Отчёты:** конверсия из этапа в этап

## 11.2 Колл-трекинг

Без него нельзя понять, какие звонки идут с каких каналов.

**Сервис:** Callibri или Calltouch
**Бюджет:** 4 000 — 8 000 ₽/мес
**Принцип:** на сайте показывается разный номер в зависимости от UTM или источника, мы знаем, с какой кампании пришёл звонок.

## 11.3 Дашборд для заказчика

В админке api.uletnayaparkovka.ru/admin/finance уже есть базовый дашборд. Расширяем:
- **Откуда приходят заявки** (UTM-метки, источник)
- **Стоимость заявки по каналам** (Директ vs VK vs органика vs Я.Бизнес)
- **Конверсия заявки в бронь** по каналам
- **Когортный анализ ретеншен**

Сводный отчёт — еженедельно отправляется на почту.

## 11.4 A/B-тесты

Никогда не катим изменения «на глаз». Тесты через:
- **Яндекс.Эксперименты в Метрике** — для веб-страниц
- **Внутренний A/B** в Я.Директе — для объявлений

Что тестируем:
- Заголовки страниц
- Цвета кнопок
- Тексты CTA
- Картинки в шапке
- Длина формы (4 поля vs 6 полей)

## 11.5 KPI блока аналитики

100% всех заявок имеют корректный источник (UTM, телефон или прямой заход).

# Глава 14. Риски и митигация

## 14.1 Риск 1: Я.Директ дорогает

С каждым месяцем стоимость клика растёт. Если CPC превысит 100 ₽ и стоимость заявки 500 ₽ — теряем рентабельность.

**Митигация:**
- Параллельно качаем SEO (через 2-3 месяца органика начнёт давать дешёвые заявки)
- Тестируем VK и Telegram (там ставки ниже)
- Усиливаем ретеншен (повторные клиенты бесплатные)

## 14.2 Риск 2: Конкурент копирует наши приёмы

Если parking24pitstop или parking-svo увидят, что мы заняли часть выдачи, они тоже усилят рекламу.

**Митигация:**
- Усиливаем UX (мобильное приложение — невозможно скопировать за месяц)
- Лояльность (баллы) — наши клиенты не уходят к конкурентам
- Локальные брендовые запросы (фокус на «улётная парковка», «улётная пит-стоп»)

## 14.3 Риск 3: Сезонность

Зимой парковка / летом — пики. Весна/осень — спад.

**Митигация:**
- Сезонные скидки (10% в спад)
- Контент о зимней эксплуатации авто на длинной стоянке (запросы вырастают)
- Ночёвка как сглаживатель сезонности (всегда нужна)

## 14.4 Риск 4: Технический сбой

Не доходят заявки, не работает калькулятор, не работает приложение.

**Митигация:**
- Self-hosted runner + cron-pull (если GitHub Actions упадёт — сервер сам пуллит)
- Логи и алёрты в Telegram (если API падает — мгновенное уведомление)
- Бэкап Postgres каждую ночь
- Мониторинг uptime (Uptime Robot)

## 14.5 Риск 5: Утечка персональных данных

Бизнес работает с персональными данными. Утечка — штрафы и потеря репутации.

**Митигация:**
- 152-ФЗ — публичная оферта и политика конфиденциальности на сайте
- Шифрование БД и backup'ов
- Регулярный аудит безопасности
- Хранение минимума данных (только то, что нужно)
- Логи доступа к данным

## 14.6 Риск 6: Команда не справляется

Если поток заявок вырастет в 5 раз, а менеджеров останется столько же — клиенты будут ждать ответа часами и уходить.

**Митигация:**
- Заранее нанимаем 1-2 менеджеров до старта рекламы
- Авто-ответ через amoCRM в течение 1 минуты «Заявка получена, перезвоним»
- Чат-бот в Telegram отвечает на 80% типовых вопросов
- KPI менеджера: 95% заявок обработаны в течение 5 минут

# Приложение В. Базовые цифры для расчёта

- 1 заявка стоит 250-350 ₽ в Я.Директе

- 15-25% клиентов возвращаются за 90 дней (если есть ретеншен-программа)

### Сезонность
- Январь: высокий сезон (новогодние перелёты)
- Февраль-март: средний
- Апрель-май: рост к лету
- Июнь-август: высокий (отпуска)
- Сентябрь-октябрь: средний
- Ноябрь-декабрь: рост к новому году

### Длина бронирования
- 1-2 дня: 40% броней (короткие командировки)
- 3-7 дней: 35% (отпуска и длинные командировки)
- 8-14 дней: 15% (отпуска)
- 15-30 дней: 7% (долгие командировки)
- 30+ дней: 3% (релокация, длинные отпуска)

- Конверсия посетителя сайта в заявку: 2-5%
